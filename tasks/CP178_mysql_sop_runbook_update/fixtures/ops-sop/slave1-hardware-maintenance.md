# 中间件-MySQL-从1标准硬件维护

## 基本信息

- **中间件**：MySQL（标识 `mysql`）
- **操作名称**：从1标准硬件维护
- **功能说明**：MySQL 从1节点停机下线、内存维修交接、起服复核与主从同步恢复验收（须在运维窗口内执行，原则上晚上10点后）。

## 运维操作输入（operation_inputs）

- `{server_ips}`：目标机器 IP（从1节点，多台用英文逗号分隔）。
- `{port}`：MySQL 实例端口。
- `{exec_host}`：执行操作的目标机器（若与 `{server_ips}` 不同请指定）。
- `{business_name}`：受影响业务线名称。

## 公告默认内容

```announcement-defaults
开始时间: 22:00
结束时间: 24:00
影响范围: 从1停机维护，流量已切换至主库，理论上对业务无感知
风险等级: 中
备注: 禁止白天高峰操作；需业务方观察审核库同步情况；执行前与业务线确认有人负责检查
```

### 执行阶段（详细步骤）

#### exec-01 — 发操作公告

- **方式**：人工
- **描述**：在公告群与研发反馈群发送停机维护公告。
- **操作步骤**：按公告模板发送停机维护公告，告知业务方本次从1硬件维护计划。
- **流转条件**：`如果 → (已发公告) → exec-02`

#### exec-02 — 业务迁移至主库

- **方式**：自动 + 人工
- **描述**：与业务同时查看当前情况，通过 Titan 进行业务迁移，确保流量切换到主库。
- **操作步骤**：
  1) 【人工执行】与业务方共同查看当前运行状态
  2) 【人工执行】通过 Titan 控制台将业务流量迁移至主库
- **流转条件**：`如果 → (业务已切换至主库) → exec-03`

#### exec-03 — 静默相关程序和端口

- **方式**：人工
- **描述**：停止并禁用 keepalived，静默相关监控。
- **操作步骤**：
  1) 在【执行机器】`{server_ips}`执行命令：`systemctl stop keepalived`
  2) 在【执行机器】`{server_ips}`执行命令：`systemctl disable keepalived`
- **流转条件**：`如果 → (keepalived 已停止且禁用) → exec-04`

#### exec-04 — 确认服务已切换到主库并观察

- **方式**：人工
- **描述**：确保服务已切换至主库，观察15分钟确认运行稳定。
- **操作步骤**：
  1) 与业务方共同观察主库运行状态 15 分钟
  2) 如果出现问题立即切回从1，停止继续操作
- **流转条件**：
  - `如果 → (观察15分钟无异常) → exec-05`
  - `否则 → 切回从1 → STOP`（见「异常与回滚」）

#### exec-05 — 停止 MySQL 实例

- **方式**：人工
- **描述**：停止目标机器上的 MySQL 实例，确认端口与连接均已释放。
- **操作步骤**：
  1) 在【执行机器】`{server_ips}`执行命令：`/usr/local/mysql/stopMysql.sh {port}`
  2) 在【执行机器】`{server_ips}`执行命令：`netstat -ntlp`，检查是否还有 MySQL 端口占用
  3) 在【执行机器】`{server_ips}`执行命令：`netstat -ant | grep {port}`，检查是否还有连接
- **流转条件**：
  - `如果 → (实例已停止 && 无残留端口 && 无残留连接) → exec-06`
  - `否则 → STOP`（优先恢复服务，见「异常与回滚」）

#### exec-06 — 停机与硬件维修

- **方式**：人工
- **描述**：机器停机，移交硬件维修。
- **操作步骤**：
  1) 对机器执行停机操作
  2) 等待硬件维修完成，并确认机器已初始化
- **流转条件**：`如果 → (机器已维修完毕并初始化) → exec-07`

#### exec-07 — 检查磁盘状态

- **方式**：人工
- **描述**：检查磁盘是否正常。
- **操作步骤**：检查磁盘挂载、容量、IO 状态是否正常。
- **流转条件**：`如果 → (磁盘状态正常) → exec-08`

#### exec-08 — 恢复 MySQL 实例

- **方式**：人工
- **描述**：启动 MySQL 实例。
- **操作步骤**：
  1) 在【执行机器】`{server_ips}`执行命令：`/usr/local/mysql/startMysql.sh {port}`
- **流转条件**：`如果 → (MySQL 实例启动成功) → exec-09`

#### exec-09 — 检查主从同步

- **方式**：人工
- **描述**：查看从1和主库的同步状态 `show slave status\G`，确认同步恢复。
- **操作步骤**：
  1) 登录 MySQL 执行：`show slave status\G`
  2) 检查 `Slave_IO_Running` 和 `Slave_SQL_Running` 是否均为 `Yes`
  3) 检查同步延迟 `Seconds_Behind_Master`，确认延迟在可接受范围内
- **流转条件**：
  - `如果 → (同步恢复 && 延迟可接受) → exec-10`
  - `否则 → (存在延迟但服务不切回到从1) → 继续观察并重试 exec-09`

#### exec-10 — 确认主库和从1同步恢复

- **方式**：人工
- **描述**：确认主库和从1的同步完全恢复正常。
- **操作步骤**：持续观察同步状态，确认无延迟积压。
- **流转条件**：`如果 → (主从同步完全恢复) → exec-11`

#### exec-11 — 恢复 keepalived

- **方式**：人工
- **描述**：恢复 keepalived 服务。
- **操作步骤**：
  1) 在【执行机器】`{server_ips}`执行命令：`systemctl enable keepalived`
  2) 在【执行机器】`{server_ips}`执行命令：`systemctl start keepalived`
- **流转条件**：`如果 → (keepalived 已恢复) → exec-12`

#### exec-12 — Titan 恢复实例

- **方式**：人工
- **描述**：在 Titan 控制台恢复该实例的注册与纳管。
- **操作步骤**：通过 Titan 控制台操作，恢复该 MySQL 实例的状态。
- **流转条件**：`如果 → (Titan 实例已恢复) → exec-13`

#### exec-13 — 解除静默

- **方式**：人工
- **描述**：在 Cuckoo 平台解除相关程序和端口静默。
- **操作步骤**：
  1) 打开 Cuckoo 平台：`http://cuckoo.tongdao.cn/web/home`
  2) 找到对应的静默记录并解除
- **流转条件**：`如果 → (已解除静默) → exec-14`

#### exec-14 — 发恢复公告

- **方式**：人工
- **描述**：在公告群与研发反馈群发送恢复公告。
- **操作步骤**：按恢复公告模板发送通知，告知业务方维护已完成。
- **流转条件**：`如果 → (已发恢复公告) → 结束`

## acceptance — 验收清单（Markdown）

**总目标**：从1节点恢复正常运行；主从同步完全恢复；监控与告警相对基线可接受。

> 与执行阶段格式对齐：每项为 **方式** / **描述** / **操作步骤** / **流转条件**。

#### acc-01 — 业务观察（一小时）

- **方式**：人工
- **描述**：与业务方共同观察一小时，确认无影响和报错。
- **操作步骤**：
  1) 与业务方共同观察业务运行状态 1 小时
  2) 检查是否有错误日志或业务报错
- **流转条件**：
  - `如果 → (一小时无异常) → acc-02`
  - `否则 → STOP`（排查问题，见「异常与回滚」）

#### acc-02 — 检查主从同步情况

- **方式**：人工
- **描述**：再次检查主从同步状态，确认同步正常。
- **操作步骤**：
  1) 登录 MySQL 执行：`show slave status\G`
  2) 确认 `Slave_IO_Running` 和 `Slave_SQL_Running` 均为 `Yes`
  3) 确认 `Seconds_Behind_Master` 为 0 或极低值
- **流转条件**：
  - `如果 → (同步正常) → 结束`
  - `否则 → STOP`（排查同步问题）

**若执行过回滚**：须书面说明回滚已完成及当前状态稳定，凭证可记入飞书 Meego 或附件截图（脱敏）。

## 异常与回滚

- **原则**：异常即 `STOP`，优先恢复服务/回滚到变更前可用状态；必要时升级值班与相关负责人。
- **最小回滚路径**：
  - exec-04 观察异常：立即将业务切回从1，停止继续操作
  - exec-05 停实例异常：重新启动 MySQL 实例并验证
  - 已下线主机：撤销维护状态并确认主机在线
  - 已切换/摘流：按预案回切或恢复流量（以业务可用性为先）
